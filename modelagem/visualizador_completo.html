PostgreSQL 16 • 3ª Forma Normal

Modelo Lógico Relacional

Normalizado em 3FN para garantir integridade referencial forte via chaves estrangeiras. A resolução de matrizes ocorre via tabela associativa (MATRIZ_COMPONENTE) e os pré-requisitos via auto-relacionamento (PRE_REQUISITO) com operador booleano ('E' ou 'OU').

    CURSO {
        varchar(10) codigo PK "Código único"
        varchar(20) sigla UK "Sigla (TADS)"
        varchar(150) nome "Nome oficial"
        varchar(50) nivel "Graduação"
        varchar(120) unidade "EAJ - UFRN"
        varchar(30) modalidade "Presencial"
    }

    ESTRUTURA_CURRICULAR {
        varchar(20) codigo_matriz PK "Ex: TADS2019"
        varchar(10) curso_codigo FK "FK para CURSO"
        int ano_versao "2019"
        int ch_total_minima "2100"
        int ch_obrigatoria "1680"
        int ch_optativa "240"
        int ch_complementar "180"
        int duracao_semestres "6"
        boolean ativa "true"
    }

    DISCIPLINA {
        varchar(10) codigo PK "Ex: TAD0102"
        varchar(150) nome "Nome do componente"
        int ch "Carga horária"
        int creditos "Créditos"
        varchar(30) departamento "EAJ"
        text ementa "Ementa detalhada"
    }

    MATRIZ_COMPONENTE {
        int id PK "ID sequencial"
        varchar(20) estrutura_codigo FK
        varchar(10) disciplina_codigo FK
        int periodo_ideal "1 a 6"
        varchar(30) tipo_vinculo "OBRIGATORIA"
    }

    PRE_REQUISITO {
        int id PK "ID sequencial"
        varchar(10) disciplina_alvo_codigo FK
        varchar(10) disciplina_requisito_codigo FK
        varchar(5) operador_logico "E ou OU"
    }

Modelo Lógico Não Relacional em Documentos

Estrutura mista: a coleção cursos embuti a grade completa por períodos (carregamento integral sem JOIN) e a coleção disciplinas gerencia o catálogo e o array de dependências para análise recursiva via $graphLookup.

classDiagram
    class CursoDocument {
        +ObjectId _id
        +String codigo "01A"
        +String sigla "TADS"
        +String nome "Tecnologia em Análise e Desenvolvimento de Sistemas"
        +Integer ano_versao 2019
        +Integer ch_total_minima 2100
        +PeriodoGrade[] grade
    }

    class PeriodoGrade {
        +Integer periodo "1 a 6"
        +DisciplinaEmbutida[] disciplinas
    }

    class DisciplinaEmbutida {
        +String codigo "TAD0102"
        +String nome "Algoritmos e Programação"
        +Integer ch 90
        +Integer creditos 6
        +String tipo_vinculo "OBRIGATORIA"
    }

    class DisciplinaDocument {
        +String _id "TAD0009"
        +String codigo "TAD0009"
        +String nome "Programação Orientada a Objetos"
        +Integer ch 60
        +CursoVinculo[] cursos_vinculados
        +RequisitoItem[] requisitos
    }

    class CursoVinculo {
        +String curso_sigla "TADS"
        +Integer ano_matriz 2019
        +Integer periodo_ideal 2
    }

    class RequisitoItem {
        +String disciplina_codigo "TAD0102"
        +String nome "Algoritmos e Programação"
        +String tipo "E | OU"
    }

    CursoDocument *-- PeriodoGrade
    PeriodoGrade *-- DisciplinaEmbutida
    DisciplinaDocument *-- CursoVinculo
    DisciplinaDocument *-- RequisitoItem

Modelo Lógico Não Relacional em Grafo

Mapeia a grade como um Grafo Direcionado Acíclico (DAG). Nós (:Curso), (:Estrutura) e (:Disciplina) são conectados por arestas direcionadas com propriedades (*Index-Free Adjacency*, com complexidade $O(1)$ por salto).
